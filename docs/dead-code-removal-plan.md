# Dead code scan & removal plan

A full-repo audit of code that no longer has a producer or a consumer, and a
phased plan to remove it without changing anything a skill user can observe.

**Scope of the scan:** every source file in `server/`, `assets/`, the template,
and all of `references/` + `SKILL.md`, cross-referenced against each other and
against the full git history (`git log -S`) to distinguish three things that
look identical in the code:

1. **Dead code** — no generation path produces it, no client calls it, no test
   needs it. Safe to remove.
2. **Legacy-compat code** — looks dead in this repo, but exists to keep pages
   generated by *older skill versions* working. Removing it breaks parity for
   existing users. Keep, and this document records why each piece stays.
3. **External-surface code** — unused in-repo, but possibly consumed by an
   embedding host outside this repo. Needs a maintainer decision.

A key structural fact that de-risks most of this: **generated pages inline
`document.css` at assembly time and carry no chrome**. Chrome (`shell.js`,
`chrome.css`, `chrome-host.css`) is injected at serve time, so chrome changes
reach every already-generated page — while `document.css` changes reach only
*newly* generated ones. Parity analysis below leans on that split.

---

## 1. Dead code — remove

### 1.1 The variant picker (the big one, ~150 lines across four files)

`.variant-page` / “multi-variant mode”: a toolbar `1 / N` navigator that pages
through multiple page variants in one file, printing only the `.active` one.

**Evidence it is dead:** it has shipped in the shell since the initial commit,
but no revision of `SKILL.md`, `references/assembly.md`, or any other reference
has *ever* documented producing `.variant-page` markup (verified with
`git grep 'variant-page' <every-rev> -- references/ SKILL.md` across all 71
commits — zero hits). The assembly procedure produces `#page` (plus nested
`.page` sheets for two-sheet documents), never variants. No test exercises it.
Because no generation path ever emitted the markup, no legacy page in the wild
carries it either — so serve-time removal is parity-safe.

**What to remove:**

- `assets/shell/shell.js`
  - the “Variant picker” section: `initVariants()`, `showVariant()`,
    `variantPages` / `variantTotal` / `variantCurrent`
  - `getActivePage()` → collapses to `document.getElementById('page')`
  - the variant re-init block in `restoreHistoryState()`
  - the `.variant-page` guard in `deleteSelected()`
  - the `.variant-page.active` fallback in `selectorWithin()` → always `#page`
  - `'variant-page'`/`'active'` class filtering in `makeContinuation()`
  - `.variant-page` in the `applySize()` and `cleanClone()` selector lists
  - the variant-nav toolbar construction in `injectChrome()` (`#mp-variant-sep`,
    `#mp-variant-nav`, `#mp-btn-prev`, `#mp-variant-label`, `#mp-btn-next`)
  - the `initVariants()` call in `init()`
- `assets/shell/chrome.css`: `#mp-variant-nav`, `#mp-variant-label`,
  `.mp-nav-btn` + its `:hover` (the nav buttons are its only users)
- `assets/shell/chrome-host.css`: `body.mp-embedded .variant-page`,
  `.page-surround > .variant-page` in the print block, and the comment in the
  `break-before` note that explains itself in terms of “display:none variants”
- `assets/shell/document.css`: the “Multi-variant mode” rules, `.variant-page`
  in the paper-background lock, in the overflow-clip scope selector, and the
  two variant print rules

`fit-cli.mjs` and `contrast-cli.mjs` already reason in terms of leaf `.page`
elements and never mention variants — no change needed there.

### 1.2 Long-poll machinery on the live channel

`GET /chat/<page>.html/messages` accepts a `wait=<seconds>` parameter (up to
300s) that parks the request on a waiter until a message arrives. **No client
ever sends it**: the shell polls with `?after=` on a fixed 1.5s interval, and
`chat-cli.mjs` never GETs messages at all. It is a leftover of the retired
push-channel design (replaced by reads in “Replace the push channel with a
read”, PR #19).

**What to remove:**

- `server/server.mjs`: the `wait` parsing and `onAbort` wiring in
  `handleChat()`; the `closeAll()` import and its call in `close()` (with no
  waiters there is nothing to settle before `server.close()`)
- `server/chat-store.mjs`: `closeAll()`, the `waiters` set, the whole
  promise/timer body of `awaitMessages()` (collapses to the synchronous
  `pending()` read — rename accordingly), and the waiter-notification loop in
  `postMessage()`

**Parity:** the response shape (`{ok, epoch, messages}`) is unchanged; a stray
`wait` param from an unknown caller degrades to “answer immediately”, which is
valid long-poll semantics anyway.

### 1.3 The unused `page` parameter on selection/fit reads

`getSelections(log, page)` / `getFits(log, page)` / `newestFirst(map, page)`
accept a per-page filter that `server.mjs` never passes — `/chat/selection` and
`/chat/fit` are global reads, and `chat-cli` filters client-side (`forPage`).
Drop the parameter and the `page === undefined` branch.

### 1.4 `mpAll()` in shell.js

Defined next to `mpq()`, called nowhere. Remove.

### 1.5 Unused chrome tokens

`chrome.css` `:host` still defines `--mp-slide`, `--mp-ease` (the retired chat
panel’s slide animation — its comment even claims chrome-host.css restates the
numbers, which it no longer does) and `--mp-notice` (“a decision is owed” —
nothing renders that state since the FIX-button redesign). No rule consumes any
of the three. Remove all three declarations and the comment.

### 1.6 Stale comments that describe retired features

Zero-risk doc rot, worth sweeping in the same pass:

- `assets/page_template.html`: the body comment says the server injects
  “toolbar, edit mode, chat panel” — there is no chat panel.
- `assets/shell/document.css` header: “the toolbar/edit/chat styles live in
  chrome.css”.
- `server/server.mjs`: the `CHROME_ASSET_FILES` comment says “the two inlined
  stylesheets and the two scripts it links” — it is three files and one script.
- `assets/shell/shell.js` `cleanClone()`: drop `'mp-chat-open'` from the body
  class strip **only if** the maintainer is comfortable no chat-era page file
  survives with that class baked in; it costs one string to keep, so the
  default is to keep it (see 3.6).

## 2. Optional trims — small wins, wire-format changes; maintainer’s call

### 2.1 `snapshot` + `edited` in the selection payload

`captureElement()` ships up to 2 KB of element `outerHTML` (`snapshot`) and an
`edited` flag with every selection notice; the store holds them, and **no
consumer reads them** — `chat-cli selection` prints label/index/text/selector
only, and its own header says “everything else about the element is in the file
on disk, which is the authoritative read anyway.” Removing them shrinks every
selection write and the store’s memory.

Cost: `server/test/selection.test.mjs` asserts `snapshot` exists, so the test
updates alongside; and any out-of-repo consumer reading the raw
`/chat/selection` JSON would lose the fields. Recommended: remove `snapshot`
(the heavy one), keep `edited` if in doubt.

### 2.2 `data-mp-paginate="off"`

An undocumented body-attribute escape hatch that disables pagination. Dead from
a skill user’s perspective, but `pagination.test.mjs` uses it to test the
opt-out spill behaviour. Recommended: **keep** — it is three lines, it is the
only way to get the pre-pagination single-sheet behaviour back, and removing it
means rewriting a test for negative value.

## 3. Looks dead, is not — legacy parity, keep

Each of these has no in-repo producer, which is exactly why they exist: their
producers are pages generated by older skill versions sitting in users’ `out/`
directories. `SKILL.md` (“Editing an existing page”) promises those pages keep
working. Recorded here so a future cleanup doesn’t mistake them for §1:

1. **`assets/shell/shell.css`** — 10-line `@import` shim for legacy pages that
   link `shell/shell.css` directly. Served via the `/shell/*` skill-asset
   route.
2. **The `/shell/*` skill-asset-first route in `serveStatic()`** and the
   `injectChromeTags()` skip for pages that already link `shell/shell.js` —
   both are how legacy self-linking pages get current chrome without
   double-loading it.
3. **`computePrintFit()` hook in `render.mjs`** — pages from pre-WYSIWYG shells
   carry that zoom pipeline; invoking it when defined keeps their PDFs
   rendering as they always did.
4. **The `'landscape'` paper alias** — `applySize('landscape')` and
   `body[data-mp-paper="landscape"]` static rules; older pages carry both
   forms.
5. **The legacy chrome sweep** — `#mp-toolbar`, `#mp-overlay`,
   `#mp-chat-panel`, `.page-break-guide` removal in `injectChrome()` /
   `cleanClone()` — is the documented cleansing path for baked-in-chrome pages
   (and `pagination.test.mjs` locks the `.page-break-guide` sweep).
6. **`mp-chat-open` strip in `cleanClone()`** — one string; cleanses chat-era
   files on their first save.
7. **`min-height: 0` inline neutralization in `applySize()`** — older pages’
   frozen inline stylesheets carry min-height sheet rules.

## 4. Decision needed — external surface

### Embedded iframe mode (`mp-embedded` / `data-mp-embedded`)

`init()` detects `window.self !== window.top`, strips the toolbar
(`chrome.css`) and the canvas chrome (`chrome-host.css`). Nothing in this repo
embeds a page and no test covers it; the only reference is a comment naming “an
embedding host like create.html” — a host outside this repo. The same applies
to the documented ability for a host to call the global `applySize()` after
load.

**Do not remove unilaterally.** If the create.html host is retired, remove the
embedded branch in `init()`, both CSS blocks, and the `mp-embedded` strip in
`cleanClone()`; if it lives, keep all of it and this section becomes its
documentation. (The variant picker in §1.1 has the same theoretical consumer;
if create.html is alive and uses variants, §1.1 moves here.)

## 5. Removal plan — phases, each independently shippable

Run between every phase, from `server/`:

```
npm test                       # the full suite drives real Chromium
```

and once per phase the end-to-end smoke: assemble a sample page per
`references/assembly.md`, then
`node server/fit-cli.mjs out/sample.html`,
`node server/contrast-cli.mjs out/sample.html`,
`node server/render-cli.mjs out/sample.html`, and a manual serve
(`server.mjs --dir <cwd>/out`) checking: toolbar renders, edit mode + selection
recorded (`chat-cli selection`), FIX path, undo/redo, zoom, print-to-PDF, and
auto-reload on a disk edit.

- **Phase 0 — baseline.** `npm install --prefix server`, run the suite and the
  smoke on the untouched tree; record results.
- **Phase 1 — zero-risk sweep.** §1.4 `mpAll`, §1.5 tokens, §1.6 comments.
  No behaviour change possible; suite green.
- **Phase 2 — variant picker (§1.1).** One commit, all four files together
  (shell.js reaching for a chrome node that chrome.css no longer styles — or
  vice versa — is the failure mode to avoid). Extra verification: the smoke
  page plus a *two-sheet* (answer-key) page, since `originSheets()` /
  continuation logic is adjacent to the removed code; grep the tree for
  `variant` afterwards expecting only `font-variant-numeric` hits.
- **Phase 3 — live-channel simplification (§1.2, §1.3).** Server-side only;
  wire format unchanged. Extra verification: `chat-cli` `selection` / `fit` /
  `status` round-trips against a running server; `selection.test.mjs` and
  `fit-report.test.mjs` cover the rest. Confirm clean shutdown (SIGINT and
  `render-cli` one-shot) still exits promptly with `closeAll` gone.
- **Phase 4 — decisions (§2, §4).** Only after the maintainer answers the
  create.html question and blesses the payload trim. Each is its own commit
  with its own test update.

Estimated total: ~200–250 lines of code and ~40 lines of stale comments
removed; no reference doc changes required (none ever documented the removed
features — that absence is the evidence they are dead).

## 6. Parity contract — what “no user-visible change” means here

- A page generated **today, before the change**, still: serves with full
  chrome, edits, selects, fixes, prints identical PDFs (chrome is serve-time;
  none of §1 touches document geometry, tokens, pagination, or print CSS).
- A page generated by an **older skill version** still cleanses and works: all
  of §3 is untouched.
- The **wire format** of every endpoint a client actually uses is unchanged
  (§1.2 removes only an unused request parameter; §2.1 is gated behind Phase 4
  for exactly this reason).
- `fit-cli` / `contrast-cli` / `render-cli` / headless pipeline paths:
  untouched by §1; re-verified each phase anyway.
- The only capability that ceases to exist is the variant picker — which
  nothing and no one could have invoked through any documented path in the
  skill’s entire history.
